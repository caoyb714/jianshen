## 动作库

- 分类：蹲 8、髋铰链 10、推 8、拉 8、核心 6、有氧与灵活 4。
- 每个动作含：动作模式、器械、难度、冲击性、关节负荷、主要肌群、是否单侧、建议组次、组间休息、步骤、要点、常见误差、注意事项、替代动作。
- `LIBRARY_REVIEWED = false`：内容由本项目参考公开基础运动资料后自行撰写，**未经专业人员逐项审核**，界面与文档必须如实呈现。
- 动作库放在代码而不是数据库：2 位用户不会新增动作，放进代码可以离线可用、随 Git 审核，也省掉一张表的 RLS 与种子流程。

## 规则引擎

输入：年龄、经验、每周天数、单次时长、器械、身体限制（须已确认）。

确定的规则：

1. 身体限制未确认 → 拒绝生成。
2. 有身体限制或年龄 ≥ 60 → 只选入门且低冲击动作，并在计划上标注需人工确认。
3. 零基础 → 只选入门动作；偶尔运动 / 规律运动 → 允许进阶动作。
4. 每周天数决定分化：≤3 天全身，4 天上肢/下肢交替，5 天以上加一个主动恢复日。
5. 组数按经验：零基础 2 组，偶尔运动入门 2 组 / 进阶 3 组，规律运动 3 组。
6. 目标次数按经验缩放，零基础取区间下沿。
7. 时长预算 = 单次分钟数 − 热身，按「组数 ×（次数 × 节奏 + 休息）」累加，超预算就停。
8. 每个训练日必须覆盖蹲 / 髋铰链 / 推 / 拉 / 核心；一周内尽量不重复同一动作（游标轮换，池子不够才回绕）。
9. 每天以 1 个灵活性动作收尾作为放松。
10. 同一份档案生成的结果完全一致（有单测断言）。

渐进负荷建议（`suggest`）：

- 有任何一次记录「训练中不适」→ 建议停止并给出替代动作。
- 最近两次全部组达到目标次数上限且难度 ≤ 7 → 哑铃 +1 kg，弹力带 +1 档，徒手 +2 次。
- 上次难度 ≥ 9 → 建议降载 5%。
- 有组次未达标 → 保持当前负荷。
- 仅记录一次 → 提示继续收集数据。
- 每 4 周为降载周（`isDeloadWeek`）。

**建议只出现在训练页提示里，不会自动改写计划。** 修改计划必须重新生成并确认。

## 数据模型变化

- `health_profiles` 去掉 `workspace_id` 唯一约束，新增 `slot`（1 或 2），`unique(workspace_id, slot)` 保证最多两个档案位。
- 新增 `training_plans`：`payload` 存 7 天计划，`status` 为 `active` / `archived`，部分唯一索引保证每个档案同时只有一份生效计划。
- `workout_logs.payload.exercises[].sets[]` 改为逐组数组 `{reps, load, done}`，数据库边界逐组校验。
- 快照改为 `profiles[]` 数组，并新增 `plans[]`。
- 本机存储键升到 `herfit.demo.v2`，首次读取会把 v1（单档案、单组次）迁移过来。

## 当前边界

- 动作库 44 个，没有示范图片或视频；只有文字步骤、要点与常见误差。
- 计划只按固定规则生成，不能手动增删某一天的动作；只能重新生成整份计划。
- 训练草稿仍未持久化，离开训练页会丢失未保存的本次记录（界面已提示）。
- 没有推送提醒、没有离线写入队列；云端写入必须等待服务器确认。
- 身体限制只做「降级为入门低冲击」处理，不做关键词排除或医学判断。
- 训练记录的删除仍只由数据库管理员执行。
