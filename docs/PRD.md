# HerFit 产品范围

来源：用户 2026-11-16 提供的完整方案，技术路线为 React PWA + Supabase + Cloudflare Pages。当前已交付阶段 0–3。

## 产品

供两个人共同管理的私人健康与运动记录系统，居家训练，器械为徒手 / 哑铃 / 弹力带。

分工：一人负责监督、记录与填写数据，另一人负责查看与执行；两个档案位都可被双方查看和填写。关注力量、体能、睡眠、精力与习惯；体重是自愿观察项，无减重指标。

文案：照顾好身体，也照顾好自己。A little better, every day.

## 已交付（阶段 0–3）

- 五个导航：首页、训练、记录、成长、我的；桌面侧栏与手机底栏。
- 两个档案位：顶部切换，本机记住当前档案；一个空间最多两位成员。
- 首页：今日训练安排、本周完成、饮水、睡眠、精力。
- 训练：按档案生成周计划（预览 → 确认 → 生效）、今日动作清单、本周安排。
- 打卡：逐组记录次数与负荷、组间休息计时、上次负荷预填、训练中换动作、不适停止、难度与感受。
- 动作库：44 个动作，按模式 / 器械 / 关键词筛选，含步骤、要点、常见误差、注意事项、替代动作。
- 记录：饮水、睡眠、精力、三餐 / 蛋白质 / 蔬果习惯、可选身体指标、训练历史。
- 成长：近 7 / 28 天趋势、训练容量、本周完成次数（监督视角）。
- 我的：档案编辑、体重显示开关、本机 JSON 导出、按档案清空、重新加载示例、添加到主屏幕指引。
- 云端：Supabase Auth + 共享空间 + RLS + 版本检查 + 幂等训练记录；演示与云端数据严格分离。

## 目前不交付

动作示范图 / 视频、推送提醒、离线写入队列、计划内单日编辑、记录删除、按肌群容量统计、经专业审核的训练处方、让模型决定训练内容。

**AI 说明层（v0.6）**：可选、默认关闭。只把已经由规则引擎算好的计划解释成人话，模型不得新增/替换动作、不得改任何数字、不得给医疗建议。首次使用需明确同意，可随时在「我的」关闭；只发送年龄、经验、每周天数、器械、限制摘要、今日动作与近 7 天统计，不含昵称、邮箱与任何标识。部署者自备 DeepSeek Key，存于 Cloudflare 加密环境变量。

## 设计

奶油白 `#FFF9F7`、主粉 `#E8B7C5`、淡紫 `#D8D0ED`、柔绿 `#C6DCCB`、正文 `#494047`；主按钮用更深玫瑰色保证对比度。底部导航固定并避开安全区。按钮触控区至少 44px，键盘焦点清晰。

## 范围判断

1. **动作库放代码而不是数据库**：两位用户不会新增动作，放代码可离线可用、随 Git 审核，并省掉一张表的 RLS 与种子流程。
2. **JSONB + 数据库边界校验**：字段还在演进，用 `valid_payload()` 在 CHECK 约束里兜底，比每次改结构都写迁移更划算。
3. **规则引擎负责决策，AI 只负责解释**：计划仍然确定、可测试、可复现；模型只在已确定的结果上写 60–120 字说明，输出不参与任何计算、不写库、失败即静默降级。这样既保留可测性，又拿到自然语言的表达力。代价是多一处外部依赖，且用户需要主动同意。
4. **双档案位而不是「一个空间一份档案」**：两人的体重与围度画在同一张趋势图没有意义；现在改成本最低。
5. **不做离线写入队列**：iOS PWA 不支持 Background Sync，写了也无法在后台重试；先保证「服务端确认后才提示保存成功」。
