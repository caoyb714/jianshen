# 训练内容与安全设计

## 现状（阶段 3 已实现）

动作库在 `src/domain/exercises.ts`（44 个动作），规则引擎在 `src/domain/engine.ts`（纯函数）。

**内容来源与审核状态**：动作文案参考公开基础运动资料（如 NHS Strength exercises）后用自己的简短文字表达，**未经专业人员逐项审核**。代码中 `LIBRARY_REVIEWED = false`，界面与文档都必须如实呈现，不得出现「已审核」字样。

**不服务的人群**：未成年人、孕产期、康复期与特定伤病治疗。档案年龄限定 18–100；有身体限制时只降级到入门低冲击动作并要求人工确认。

## 计划生成规则

1. 身体限制未确认 → 拒绝生成（`restrictions-unconfirmed`）。
2. 器械为空 → 拒绝生成。
3. 有身体限制或年龄 ≥ 60 → 只选「入门 + 低冲击」动作，并在计划上标注需人工确认。
4. 零基础 → 只选入门动作；偶尔运动 / 规律运动 → 允许进阶动作。
5. 每周天数决定分化：≤3 天全身；4 天上肢/下肢交替；5 天以上额外安排一个主动恢复日。
6. 组数：零基础 2 组；偶尔运动入门 2 组、进阶 3 组；规律运动 3 组。
7. 目标次数按经验缩放，零基础取区间下沿；计时动作按 0.7 / 1 / 1.3 缩放。
8. 时长预算 = 单次分钟数 − 热身时间；每个动作按「组数 ×（次数 × 节奏 + 休息）+ 切换」估算，超预算就停止加动作。
9. 每个训练日必须覆盖蹲 / 髋铰链 / 推 / 拉 / 核心；一周内用游标轮换，尽量不重复同一动作。
10. 每天以 1 个灵活性动作收尾；每日固定 3–5 分钟热身提示。
11. 同一份档案生成的结果完全一致（单测断言），不做随机化。

## 渐进负荷规则

`suggest()` 只给建议，**不会自动改写计划**。修改必须重新生成并确认。

| 条件                                         | 建议                                 |
| -------------------------------------------- | ------------------------------------ |
| 任一次记录「训练中不适」                     | 停止该动作，给出替代动作             |
| 最近两次全部组达目标次数上限，且两次难度 ≤ 7 | 哑铃 +1 kg；弹力带 +1 档；徒手 +2 次 |
| 上次整体难度 ≥ 9                             | 降载约 5%                            |
| 上次有组次未达标                             | 保持当前负荷                         |
| 可用记录少于两次                             | 继续收集数据，不给建议               |
| 每 4 周                                      | 降载周（`isDeloadWeek`）             |

## 安全边界

1. 不根据身高体重推算训练处方；不使用 BMI 做诊断。
2. 不提供减重目标、热量赤字或极端节食建议。
3. 疼痛、头晕或异常不适 → 立即停止并记录，不做「坚持一下」的鼓励文案。
4. 严重或持续不适 → 提示寻求医疗帮助。
5. 身体限制不做关键词排除或医学判断，只降级并要求人工确认。
6. 动作错误示范会带来风险，因此每个动作都写「常见误差」与「注意事项」。
7. 弹力带相关动作都提示检查裂口与固定点承重。
